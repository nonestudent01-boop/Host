UZL BOT HOST — ADVANCED ADMIN SYSTEM
====================================

DELIVERABLE
-----------
Python backend:
    uzl_admin.py

Requirements specification:
    UZL_ADMIN_REQUIREMENTS.txt


1. ADMIN SYSTEM
---------------

Roles:
- ADMIN
- SUPERADMIN

The system must provide:
- Web admin panel API
- Admin slash-command interface
- Server-side authorization
- RBAC
- Audit logging
- Rate limiting

Never rely only on hidden frontend controls.

8. FILE MANAGER
---------------

Allowed:
- Browse folders
- Open text files
- Read files
- Download files
- Upload files
- Rename files
- Delete files
- Create files
- Create folders

Admin file access must be restricted to the selected user's selected bot storage.

Reject:
- ../
- ..\
- absolute paths
- filesystem root access
- symlink escapes
- cross-user access
- cross-bot access

Every operation must be server-side validated.

10. BROADCAST
-------------

Create provider abstraction:

BroadcastProvider

Initial provider:
- Platform configured notification/channel provider.

Supported messages:
- Announcements
- Maintenance notifications
- Deployment notices
- System alerts
- General messages

Audience:
- ALL USERS
- ACTIVE USERS
- SUSPENDED USERS
- USERS WITH BOTS
- USERS WITH RUNNING BOTS
- CUSTOM USER SELECTION

12. BROADCAST CONFIRMATION
--------------------------

Before sending:

Recipients:
X users

Message preview:
[message]

Buttons:
CANCEL
SEND BROADCAST

Large broadcasts require additional confirmation.


13. BROADCAST QUEUE
-------------------

Never send thousands of messages inside a normal HTTP request.

Use:
- Background queue
- Batch processing
- Retry
- Exponential backoff
- Provider limits
- Failure handling

Never bypass provider rate limits.

18. SECRET PROTECTION
---------------------

Never automatically reveal:

- Passwords
- Password hashes
- Session tokens
- Authentication tokens
- API keys
- Runner private keys
- Encryption keys

SECRET environment variables display:

---

Do not store secret values in audit logs.


19. SECURITY
------------

Implement:

- RBAC
- Server-side authorization
- Secure sessions
- CSRF protection where applicable
- Rate limiting
- Input validation
- File validation
- Path validation
- Ownership validation
- Secret redaction

Never trust client supplied:
- userId
- botId
- file path
- permission
- role


20. STORAGE SECURITY
--------------------

Recommended:

BOT_STORAGE_ROOT/
    user/
        <user-id>/
            bot/
                <bot-id>/

The selected bot's storage directory is the maximum file-access boundary.

Prevent:
- path traversal
- absolute paths
- symlink escape
- cross-user access
- cross-bot access

----------------------

The Python application can run as a Render Web Service.

Recommended production architecture:

    ↓
UZL BOT HOST API

Background Worker
    ↓
Broadcast queue worker

Persistent database:
    ↓
Users
Bots
Deployments
Admin roles
Audit logs
Broadcasts
Broadcast deliveries

Do not rely on in-memory dictionaries for production persistence.
